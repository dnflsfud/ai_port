## 1. [P1] 동일한 이상 데이터로 다시 실행하면 HOLD가 자동 해제된다

- 위치: [run_variant.py:630](../../run_variant.py#L630), [metrics 덮어쓰기:570](../../run_variant.py#L570), [운영 게이트:672](../../scripts/validate_portfolio_bundles.py#L672).
- `annotate_tg_ratio_jump()`는 마지막으로 정상 승인된 데이터가 아니라, 같은 출력 폴더의 직전 `metrics.json`과 비교한다. 이번 실행에서 이상을 발견해도 그 파일을 새 값으로 덮어쓴다.
- 재현: 목표주가/주가 중앙값이 **1.0 → 1.5**로 급변하면 `|log(1.5)| > 0.25`이므로 첫 실행은 `HOLD`. 동일한 1.5를 다시 실행하면 비교 기준도 1.5가 되어 jump 목록이 사라지고, 다른 조건이 정상인 경우 **`PRODUCTION`**으로 바뀐다.
- 1.5는 별도 절대 범위 `[0.6, 1.7]` 안이므로 절대 범위 검사도 막지 못한다. 이는 최소 입력으로 실제 두 함수를 호출해 확인한 상태 전환이다. 현재 운영 데이터에서 이미 이런 상태 전환이 발생했다는 뜻은 아니다.
- 수정 방향: 정상 승인된 기준 데이터와 직전 실행 데이터를 분리하고, 해결되지 않은 jump는 유지한다. 명시적 해제 또는 정상 기저 복구가 있어야 경고가 해제되도록 한다.

## 2. [P2] 미국 휴장일에 발생한 실적발표 이벤트가 삭제된다

- 위치: [data_loader.py:1840](../../src/data_loader.py#L1840), 소비 경로 [backtest.py:627](../../src/backtest.py#L627), [운영 PEAD 호출:1988](../../src/backtest.py#L1988).
- S18.7의 `business_day_calendar_enabled: true`는 모델 날짜를 `BusinessDays`로 줄인다. `_load_earnings_timeline()`은 발표일과 모델 날짜의 교집합만 남기므로, 휴장일 발표를 다음 거래 가능한 날짜로 옮기지 않고 제거한다. PEAD는 이 필터링된 이벤트를 사용한다.
- 현재 워크북에서 평일 휴장일 발표 **10건/7종목**이 제거된다. 실제 운영 백테스트 기간(2019-01-29 이후)에 해당하는 것은 **7건/5종목: HSBA, MDT, PG, RIO, WMB**다.
- 예: 2022-02-21의 HSBA·WMB, 2023-02-20의 MDT·WMB. 해당 발표를 관측한 다음 거래일에 새 이벤트가 없으므로 PEAD 감쇠 계산이 새 발표로 재설정되지 않는다. 실제 점수 차이는 양수 revision 여부에 따라 달라진다.
- 최소 재현에서도 7월 3일 발표 1건이 달력 정렬 후 0건으로 사라졌다. 성과 영향(ΔIR)이나 주문 비중 차이는 측정하지 않았다.
- 수정 방향: 이벤트 날짜를 보존한 뒤 발표 시점을 반영하여 최초로 거래 가능한 모델 날짜에 매핑한다. 동일 거래일로 모이는 여러 이벤트도 보존·통합해야 한다.

## 3. [P2] 다음 리밸런싱 안내가 운영 거래일 달력과 다르다

- 위치: [export_operating_data.py:166](../../scripts/export_operating_data.py#L166).
- 백테스트는 `BusinessDays`의 21개 행을 세지만, `build_rebalance_metadata()`는 미래 일자를 `pd.offsets.BDay()`로 계산한다. 이 오프셋은 주말만 제외한다. 내보내는 달력 이름도 여전히 `weekday_index`다.
- 현재 저장된 운영 백테스트의 각 리밸런싱 시점에서 다음 일자를 예측하고 실제 다음 리밸런싱과 비교하면 **91개 구간 중 60개가 불일치**한다.
- 예: 2025-12-03 시점의 안내는 **2026-01-01**, 실제 엔진의 다음 리밸런싱은 **2026-01-05**. 2026-06-05 시점 안내는 **2026-07-06**, 실제는 **2026-07-08**이다.
- `next_rebalance_is_estimate`가 있어 추정치라는 표시는 하지만, 엔진과 다른 달력을 쓰는 체계적 오차는 해소하지 않는다. 이 문제는 안내/운영 메타데이터의 오류이며, 저장된 백테스트의 실제 체결 날짜가 이 함수 때문에 바뀌는 것은 아니다.
- 수정 방향: 엔진과 export에 동일 거래일 달력 서비스를 사용한다. 원본 `BusinessDays`가 미래까지 제공되지 않을 경우 미래 거래소 달력을 별도로 준비하고, 같은 규칙으로 검증한다.

## 4. [P2] 기존 모델·비중과 새 데이터·설정을 섞는 export를 충분히 차단하지 않는다

- 위치: [export_operating_data.py:1362](../../scripts/export_operating_data.py#L1362), [캐시 검사:1097](../../scripts/export_operating_data.py#L1097), [최종 날짜 비교:1136](../../scripts/export_operating_data.py#L1136).
- export는 현재 YAML로 새 `UniverseData`를 읽은 후 기존 `backtest_result.pkl`을 재사용한다. 호환성 검사는 최신 비중의 종목/순서와 마지막 수익률 날짜만 비교한다. 전체 날짜 인덱스·데이터 빈티지·학습 설정의 일치는 검사하지 않는다.
- 최소 재현: 캐시는 `[7/2, 7/3, 7/6]`, 현재 데이터는 `[7/2, 7/6]`이고 마지막 수익률도 10%와 21%로 달라도 호환성 검사를 통과한다. 이는 해당 검사 함수의 누락을 입증한다. 전체 export는 뒤의 수익률 귀속 검증에서 가격/수익률 변화 일부를 추가로 잡을 수 있으므로, 이 입력으로 전체 번들이 통과했다고 주장하지 않는다.
- 특히 **가격·날짜·종목이 그대로인 펀더멘털 정정**이나 **학습 설정 변경 후 export만 실행**하는 경우, 과거 모델 예측·비중과 새 데이터로 계산한 설명/예상 주문이 섞일 수 있다. config drift도 현재는 경고 전용이며 운영 상태를 막지 않는다([validate_portfolio_bundles.py:345](../../scripts/validate_portfolio_bundles.py#L345)).
- 현재 운영 번들이 실제로 서로 다른 빈티지를 섞었다고 확정한 것은 아니다. 정상 자동화는 백테스트 뒤 export를 실행하지만, 두 단계 사이의 데이터 갱신 및 수동 export 경로가 남아 있다.
- 수정 방향: 저장된 resolved config와 입력 빈티지를 export 시작 시 검증하고, 전체 날짜/종목 계약도 비교한다. 불일치하면 재계산을 요구하거나 해당 실행에 사용된 데이터 스냅샷으로 export한다.

## 검증 범위와 제외한 주장

- 기존 테스트 **815개 모두 최종 통과**. 첫 전체 실행은 801 passed / 14 failed였으나, 실패 14개는 감사자가 `--basetemp`를 프로젝트 내부에 지정하여 번들 테스트의 절대/상대 경로 가정과 충돌한 것이었다. 해당 모듈을 기본 임시 디렉터리로 재실행해 **24/24 통과**했다. 최초 경로 충돌을 운영 코드 오류로 분류하지 않았다.
- Python 3.12.10, pandas 3.0.2, ECOS 설치 확인. 테스트 실행에는 원본 Python 경로의 샌드박스 접근 제한 때문에 권한 확장이 필요했고 정상 실행됐다.
- 신호는 완성된 오버레이 이후 1거래일 지연된다. 시뮬레이션은 진입 비중으로 당일 손익을 반영한 후 종가 리밸런싱을 처리하고, 실행 비중을 공통 MVO 제약에 다시 투영한다. 이번 검사에서 이 정상 경로의 새 시점 오류는 확인하지 못했다.
- `Factor_Returns`를 달력 축소 후 복리 재계산하지 않는 경로는 합성 입력에서 문제가 발생했다. 그러나 **현재 원본의 비율 수익률 팩터는 보존된 가격 대비 1bp 초과 불일치가 0건**이었다. 변동성·금리 등 수준 변화 열을 비율 수익률과 잘못 비교한 결과는 제외했다. 따라서 현재 운영 결함의 주요 항목에 포함하지 않았다.
- 기존 감사의 공분산 추정 분기·비수렴 집계·빈티지 기록 시점 같은 잔여 항목을 이번에 새로 발견한 오류로 중복 집계하지 않았다.
